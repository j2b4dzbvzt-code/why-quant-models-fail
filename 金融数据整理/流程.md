# 数据整理：面向量化研究与交易的顺序流程

> **英文摘要（English summary）：** A practical sequence for building research data around a specific strategy and decision clock. It covers source selection, security identity, corporate actions, missing data, point-in-time joins, and market-specific tradability checks.

> **文件定位**：这是一份新编的流程文件，重点回答量化项目里“先做什么、后做什么、采用什么口径、为什么、怎样筛选、哪里会失真”,文件把数据按策略工作流串起来。
>
> **市场规则核验日期**：2026-09-28。市场规则、交易时段和供应商字段会变，历史回测应按事件发生时有效的规则版本重放。下面的流程是研究与工程框架，不替代交易所、经纪商、清算机构或数据供应商的现行规范。

## 1. 先明确量化数据整理的顺序

数据整理不是“下载行情—补缺失—算指标”。正确顺序是先定义策略要回答的问题和可执行条件，再决定数据口径。否则即使每张表都没有空值，也可能把未来公告放进历史、把无法成交的涨停价当成收益、把后复权价当成订单价格，最后得到无法复现的结果。

所有策略都可以沿着这条主链执行：

```text
定义策略主张与决策时点
  → 定义可交易证券池和市场规则版本
  → 采集不可变原始数据及来源时间
  → 规范证券身份、时区、单位、事件和版本
  → 做点时过滤、异常处理和公司行为核算
  → 选择与研究问题匹配的价格/成交/基本面口径
  → 生成信号、标签和可投资筛选
  → 按真实可下单时点模拟执行和成本
  → 以持仓、现金流和公司行为核算收益
  → 做样本外、稳健性、容量和生产监控
```

每条数据至少回答五个问题：它属于哪个证券；事实何时发生；策略何时能看到；经过什么转换；能否按该记录模拟真实交易。原始层不得被复权、填充、去极值或供应商更正覆盖。派生表应保存 `source_id`、`security_id`、`event_time`、`available_at`、`version_id`、`transform_version` 和质量标记，保证任意样本都能反向追溯。

### 1.1 先定义研究目标与执行假设

在取数之前，写清楚以下内容：

| 先确定的项目 | 要回答的问题 | 为什么先定 |
|---|---|---|
| 预测目标 | 预测 raw 价格变动、含分红总回报、波动、成交概率，还是执行成本？ | 决定价格口径、标签和公司行为处理 |
| 决策时点 | 盘前、盘中、收盘后，还是财报发布后？信号何时冻结？ | 决定哪些信息已可用，以及最早何时能下单 |
| 交易对象 | A股普通股、ETF、ADR、美国普通股、期货还是期权？ | 决定单位、公司行为、交收、回转和保证金规则 |
| 持有与调仓 | 目标持有期、调仓时点、是否允许做空或隔夜？ | 决定收益区间、融资融券/借券数据和成本模型 |
| 基准与币种 | 本地币种还是折算为统一基准币种？ | 防止把汇率收益混入证券 alpha，或反过来漏算汇兑损益 |
| 容量 | 账户规模、参与率上限、单票/单 venue 上限？ | 决定成交量、盘口深度和冲击成本应采用何种粒度 |

目标定义模糊时，不要先把所有指标统统做成“复权价”或“标准化收益”。例如，“下一交易日涨幅”是价格预测标签；“实际持有收益”则要把分红、拆股、现金、费用和汇率纳入账本，两者可能不同。

### 1.2 统一事实时间、可用时间和生效时间

不要把日期字段当成同一种时间。建议至少区分：

| 时间 | 典型例子 | 主要用途 |
|---|---|---|
| `event_time` | 成交撮合、报价更新、宏观数据所属期 | 还原事实发生的顺序 |
| `published_at` | 公司公告或宏观发布首次公开的时间 | 界定公众可知时间 |
| `received_at` | 供应商或策略系统实际收到时间 | 还原链路延迟和当时可用状态 |
| `available_at` | 经过解析、校验后策略真正可读取的时间 | 点时回测的准入条件 |
| `effective_at` | 拆股除息生效、分类变更或规则切换时间 | 处理经济效力何时开始 |
| `recorded_at` | 数据库写入、修订或撤回时间 | 重放历史版本和审计 |

在历史决策时点 `t`，默认只纳入 `available_at < t` 的信息；时间戳恰好相等时，只有可靠的事件顺序能证明数据先于决策，才允许使用。对有生效日的变化，还要按其定义判断是否已经生效。公告只有日期、没有可靠时分秒时，保守地从下一个可交易时点使用。盘后公告不能用于当日收盘前的信号；供应商次日才送达的数据也不能假设前一晚已能使用。

时间戳统一存 UTC，保留原始交易所当地时间和原时区。A股不切换夏令时；美股使用美东时间，夏令时会改变 UTC 偏移。日线日期要由各市场交易日历产生，不能用自然日硬对齐。美股盘后和即将上线的夜间交易还会带来跨自然日交易日期问题，必须按交易所的 session/trade-date 定义来切分。

### 1.3 建立点时证券池，而不只过滤今天仍上市的股票

证券主表要有稳定实体 ID、证券 ID、上市 ID、ticker/symbol 生效区间、交易所、证券类别、币种、股数/合约乘数、板块、上市/退市时间和状态。每日选股都要从“当时已上市且当时可交易”的证券池开始，并保留暂停、风险警示、退市整理、并购换股和代码迁移记录。

不能把今天的指数成分、行业分类、流通股本、风险标签或借券名单回填给过去。否则即使价格和财报本身没有未来数据，也会产生幸存者偏差、分类前视或可投资性前视。

## 2. 对原《金融数据整理实务手册》的逐项核验

下表是对原手册内容的实际性审阅，不是对书中观点照抄。结论以原手册章节和代码为对象；需要修正的地方已经在原文件补充复权说明，策略流程则在本新文件按顺序重新组织。

| 原理部分 | 核验结论 | 实务修正或适用边界 |
|---|---|---|
| 总原则：当时可见、可交易、可追溯 | 正确，且是整份手册最重要的原则 | 还应把决策时点、证券池、市场规则版本和成交假设写入策略规格，避免“数据可用”与“订单可成交”被混为一谈 |
| 时间字段和证券身份 | 正确 | `available_at` 应含供应商延迟、解析与系统延迟；ticker 仅是带有效期的别名。合并前还需处理修订、更正、撤回和同一时刻多版本的确定性排序 |
| A股与美股交易制度 | 基本正确，但制度按市场、品种和日期变化 | 2026-07-06起沪深交易规则修订生效。上交所此次将基金收盘阶段由连续竞价调整为收盘集合竞价（与沪市股票收盘机制一致），并将盘后固定价格交易适用范围扩展至全部A股和交易型开放式基金（ETF）；另将主板风险警示股票涨跌幅限制由5%调整为10%。这些变化要按交易所、板块、证券状态和日期分别编码，不能泛化到所有A股。纳斯达克每周五天、每日23小时交易模式（23/5）的夜间场次截至本文件核验日仍是未来安排，已公告计划于2026-12-06开始；不可把计划时段当成当下历史行情。美股核心时段、盘前盘后和各经纪商可交易时段应分开 |
| T+1 | 原手册区分“交收周期”与“日内回转”是正确的 | A股股票通常有买入后当日不能卖出的回转限制，具体品种另查；美国标准T+1是结算周期，不等于禁止同日买卖。还应单独建模资金可用、证券可卖、融资/借券及账户规则 |
| 涨跌停、停牌与LULD | 正确，但不能简化成“美股没有限制” | A股限制按交易所、板块、风险状态、上市阶段、日期配置；触板不等于可成交。美国个股存在LULD价格带/交易暂停、监管停牌及市场熔断， extended hours 适用机制也可能不同。报价越带或处于暂停时不能按盘口表面价格估计可成交性 |
| Raw、前复权、后复权、总回报 | 分类方向正确，原手册前文已列出简要用途 | 本文件所对应的原手册补充了“后复权何时用”、与账户收益的区别、跨事件现金流和拆股成交量单位。执行价始终应使用当日真实市场价格；HFQ 不等于净值账本 |
| 原前复权函数 `front_adjust_asof` | PIT 思路正确，但原示例有实际缺陷 | 原代码没有截断 `raw_close` 中 `as_of` 之后的价格，也没有拒绝混用无时区与有时区时间。原手册中的函数已替换为先校验时区、截取未来价格、再过滤未来可用/未生效公司行为的版本。它仍只适合简单价格因子，不处理复杂权益会计 |
| 逐笔成交清洗和主动买卖方向 | 原则正确 | 成交撤销/更正应按供应商协议还原状态；特殊成交条件不要一概删除，按研究目标保留原值并建立 inclusion flag。主动方向是交易所标记、报价匹配或 tick rule 得到的代理，必须记录未知与判定质量 |
| 报价与订单簿 | 结构化建议正确 | 美股单一交易所 direct feed 只能说明该 venue；SIP 是综合视图，也不等于完整可见的隐藏流动性。缺少订单生命周期、序号或拍卖数据时，不应声称复原了精确队列位置 |
| 基本面、公告和宏观的点时合并 | 原理正确，原示例已加强 | 当前原手册代码按证券和特征合并、要求时区明确、检测 UTC 规范化后的同一可用时点重复版本，并将容忍期（tolerance）改为调用者按字段经济有效期决定。季度财报不应无限向前沿用；修订版本要留档 |
| OHLCV 与 bar 构造 | 用途与质量规则正确 | OHLCV 不能确定一根 bar 内先止盈还是先止损，也无法复原队列。活动 bar 会改变采样时钟，但不会自动令数据独立、正态、平稳或“等信息”；这需要样本统计验证 |
| 成交笔数/成交量/成交额柱（tick/volume/notional bars） | 作为不同活动时钟的说明正确 | 成交额柱（传统 dollar bars）按证券报价币种计算；A 股人民币金额与美股美元金额不可直接比较。阈值不通用，拆股、合约乘数、盘后成交和异常大单仍影响结果。未达阈值的收盘尾段要标记，不能误当完整 bar；整笔归入后超阈值的含义也要固定 |
| 不平衡/连续方向柱（imbalance/runs bars） | 逻辑正确，名称容易被误解 | 主动方向往往估算而来，所谓不平衡只是订单流不平衡代理，并不是直接观察“信息量”。方向分类、预期长度、指数加权移动平均（EWMA）和阈值都应只用过去数据估计，并做替代算法敏感性分析 |
| CUSUM 事件过滤器 | 原代码是可用的变体 | 原示例累计对数收益并使用对数收益阈值；书中相关函数常以输入序列的差分和固定阈值表达。两种方案的量纲不同，不能直接搬用同一个 `h`。阈值应点时估计并报告事件覆盖率、漏报与选择条件 |
| 期货连续序列换月代码 | 原手册已提示存在局限，但代码不应作为真实换月盈亏 | 用新合约首个 open 与旧合约上一根 close 算 gap，会把换月价差和隔夜市场变动混在一起。研究序列应使用同步时刻的旧/新合约价格并记 roll rule；实际PnL仍逐合约按成交、合约乘数、持仓和费用计算 |
| 动态篮子 `basket_wealth_index` | 作为“滞后权重的日频百分比收益组合”简化示例成立 | 它不是完整 ETF Trick：无持仓数量、现金、融资、期货乘数、汇率、分红账本和冲击成本。对股票篮子可用于原型校验；生产级组合需从数量和现金流逐笔记账 |
| 标签重叠、平稳化和结构突变 | 正确且边界说明重要 | 还要在训练/验证切分时按标签结束时间 purging，并按策略频率做 embargo；任何差分、分位数或标准化参数只能由训练窗口拟合，不能全样本估计后回填 |
| 数据质量检查与流程图 | 方向正确 | 增加版本回放、晚到/撤销消息、行情缺口与供应商更正的影响报告。通过字段检查不等于经济正确；高质量的执行回测还要有费用、容量、队列和不可成交状态 |

**核验后的总判断：**原手册的底层原则和数据类别划分总体可用；容易误用的环节是复权字段语义、历史可用时间、bar 被赋予过强统计含义、连续期货价被误认为收益，以及把简化篮子代码看作完整账本。交易制度需保存带有效日期的规则表。上交所、深交所2026年修订规则自2026-07-06施行；Nasdaq已宣布新夜间交易时段拟于2026-12-06启动，因此在2026-09-28的实际数据工程中只能为未来规则做准备，不能把该时段回填到历史或当前成交记录。

## 3. 按量化研究到交易的具体场景走流程

下面每个流程都按同一逻辑写：研究目标 → 原始数据 → 清理顺序 → 口径和筛选 → 信号可用时点 → 执行与收益 → 检验和坑。实际项目可以删去不相关数据，但不能跳过点时与可交易性检查。

### 流程A：A股/美股日频横截面因子选股

**目标**：在每个调仓时点从当时真实可投资股票中排序，预测未来一段时间的价格表现或总回报。

**需要的数据**：日线 raw OHLCV 与官方收盘/竞价信息；证券主表和历史上市/退市状态；交易日历和市场规则；公司行为台账；点时财报；历史指数/行业成分；流通股本；必要时借券、交易费用和汇率。

1. **冻结策略规格。** 例如“每个交易日收盘后计算因子，下一交易日开盘/集合竞价执行，持有20个交易日”。若决策时点是收盘后，信号不能假装在同一收盘价成交；若信号要在收盘集合竞价提交，就必须使用提交截点前可知字段，并在竞价数据中模拟。
2. **先生成当日可投资证券池。** 用历史生效日期过滤尚未上市、已退市、停牌、无价格、交易状态不允许下单的证券；保留风险警示与涨跌幅规则状态。不要因今天已退市而删掉历史样本，也不要把今日指数成分回填为过去成分。
3. **核对日线定义。** raw close 是官方收盘竞价价、最后一笔连续交易价，还是供应商收盘？A股盘后固定价格交易不应混成收盘前连续竞价；美股日线需区分核心时段收盘拍卖与盘后成交。OHLC 的 session、成交量范围和调整类型必须一致。
4. **对齐公司行为与基本面版本。** 股价类特征用点时拆股/公司行为连续序列或收益率构造；财报按 `available_at` 对齐到每个证券每个决策时刻。财报期末不等于公告时刻。修订数据要用当时版本，不能只取最新重述值。
5. **按经济意义过滤异常。** 排除供应商坏价、重复bar、错误币种、零成交却有虚构 OHLC 等；对停牌和无成交记录设状态字段，而不是把价格前向填充后视为可交易。极端收益先关联拆股、分红、退市、并购、复牌和涨跌停事件，再决定是否保留/限幅。
6. **在每个日期做横截面处理。** 仅用当日点时证券池；行业/市值中性化只用当时行业和股本。Winsorize/标准化参数按日期横截面计算，且明确微型股、低价股、ADR/ETF 是否参与。不能先看完整历史分布再定统一门槛。
7. **形成信号并冻结版本。** 因子表记录 decision_time、可用数据版本、证券池版本、因子代码版本和预测标签口径。收盘后公布的新闻、宏观和分析师值只能影响下一个可交易时点。
8. **把信号转换为下单目标。** 加入交易单位/零股规则、可卖股数、A股T+1、借券可得性、涨跌停/停牌、参与率上限和组合集中度。A股股票买入后同日通常不可回转卖出；美股标准T+1交收并不等于不能日内回转，但账户、借券和券商权限仍会约束交易。
9. **用实际可交易价格算收益。** 信号价格和成交价格分开；按 next open/auction/限价成交模型进入持仓。含分红持有收益用事件现金流或经过验证的总回报序列；扣佣金、交易所费用、税费、冲击、融券费用和 FX。
10. **检查策略能否被现实买到。** 报告覆盖率、换手、容量、涨跌停未成交比例、停牌跨越天数、退市回收值、借券失败比例、成本前后收益。横截面收益漂亮但只来自无法成交的证券，不能视作有效信号。

**A股额外细节**：按沪、深、北交所和板块/证券状态建立可生效的规则表；限制价格、报价单位、交易阶段、申报数量和卖出可用时间不能用一个“全市场常数”。截至2026-09-28，上交所2026版规则于7月6日生效，收盘竞价和盘后固定价格阶段要体现在行情解释中；深交所也应采用自己的当期规则版本。

**美股额外细节**：普通核心时段目前按Nasdaq市场页面为9:30–16:00 ET，盘前/盘后数据分别标记；不同交易所、ATS和经纪商覆盖不一。Nasdaq计划2026-12-06开启9:00 p.m.–4:00 a.m. ET新夜间时段，当前研究需将其视为将来规则，未来启用后仍要独立定义trade date、数据覆盖和流动性，不与盘前或核心时段混算。

### 流程B：趋势、均线、突破和其他价格技术信号

**目标**：识别价格路径形态，同时不把公司行为的机械跳变误认为价格趋势，也不把调整价当作历史交易价格。

1. 从证券级 raw OHLCV 开始，先处理交易日历、停牌、复牌、错误成交、开收盘竞价定义和盘前盘后边界。
2. 建公司行为事件表，区分拆股/合股、现金分红、送转、配股、分拆上市、合并和ADR比例变动；保存公告、记录、生效、支付时间以及修订版本。
3. 先写明技术信号要预测哪种收益。若预测下一时段的市场价格变化，特征可用仅按拆股连续的价格/收益或点时价格比例；若关注含分红长期总回报，则将分红作为收益现金流，不要偷偷把目标换成总回报。
4. 对只依赖比例和收益的信号，明确用 raw 价格收益、拆股调整收益，还是总回报收益。以绝对价位定义的信号（固定止损、突破某个美元价位、低价股筛选）必须回到当日raw价格，并记录策略阈值随拆股如何迁移。
5. 用滚动窗口计算特征时，逐日使用截至当时可得的因子和价格。以当前日期为锚的前复权会把之后发生的因子反向改写更早历史，历史回测应按各自决策日重建；固定早期锚点、逐日向未来累计已生效事件的后复权，通常不会因之后的新事件改写事件前的值，但要防供应商修订和锚点重定义。两者都不是当日实际成交价，绝对价位、交易门槛和下单仍用raw。
6. 将信号在可实现的执行点落地。收盘价计算的均线突破只能按下一可交易时点成交；若次日停牌、涨跌停或盘前跳空，要按交易模型处理，不默认按昨日收盘成交。
7. 对拆股和除息日做事件诊断。人工核对原始前后收盘、官方参考价、调整因子和原始成交量；检查信号在除息日是否出现不合理跳变。

**常用选择**：图表阅读和“当前尺度回看历史形态”通常用前复权，前提是接受历史值随新事件回写；“从早期起点看累计增长曲线”通常用后复权或总回报指数；真实交易和成交回放用 raw 价格；真实组合收益以持仓账本重放为准。更完整的后复权边界和公式见[原理手册](./原理.md)的 OHLCV 小节。

### 流程C：股息、拆股和长期总回报/财富指数

**目标**：回答“持有某证券期间账户实际增加了多少财富”或制作可比累计收益曲线。此流程需将市场价格、股数和现金分配分开记账。

1. 获取原始成交价及除息/生效/支付事件；校对普通分红、特别分红、送转、拆股、配股、spin-off、ADR ratio change、现金替代和并购对价。
2. 决定投资者身份和会计假设：税前/税后、股息是否复投、复投日/价格、交易费、币种/换汇时间、分数股处理。不能默认所有供应商的“总回报”采用同一假设。
3. 记录初始持仓股数 q 和现金 C。事件发生时先按公司行为条款调整 q 和应收/应付现金；除息日价格跳变本身不是账户亏损的全部，现金应收需要进入净值。
4. 如股息复投，按明示的复投时点和可执行价格，把扣税后现金换成新股数；如果不复投，保留现金并按现金管理规则计息或忽略。两种口径会产生不同的长期路径。
5. 对拆股，把股数乘以新旧股换算比，把每股raw价格自然变化留在市场数据里。检查股数变化和价格变化前后市值连续性；不要对split和cash dividend使用同一个volume调整规则。
6. 对配股和spin-off按条款估值：是否可参与、是否能卖出、零碎权益如何现金结算、子公司何时有可交易价格。若资料缺失，明确做敏感性区间，不应静默按零价值。
7. 逐日以 raw 市值 + 现金 + 应收分配 - 负债计算净值，换算基准币种时用相应时点 FX；扣除实际费税后计算组合收益。
8. 以总回报指数或供应商后复权作为独立核对列，对齐起点、复投假设和公司行为版本，比较累计回报差异。差异显著时追查特别分红、税、复投价格、ADR比率、数据修订或供应商因子算法。
9. 输出两条线：市场总回报指数与策略账户净值。前者便于比较证券，后者用于绩效归因、可实现性和投资者回报。

**公式检查**：在不发生额外权益、且每股分红 D 按初始持股单位计量的简化场景，期末总回报近似为 `(期末市场价值 + 现金分配) / 期初投入 - 1`。若 1 股旧股变为 k 股新股，期末市场价值为 `k × 期末每股raw价`，但配股、spin-off、多次拆分、税费和币种需逐事件核算。这个总回报式是账户收益的简化核算，不是生成复权OHLC价格的通用代码。

### 流程D：财报、公司公告和宏观事件策略

**目标**：研究市场在真实获知新信息之后的反应，避免用报告期或修订后最终数值冒充当时披露。

1. 建事件主键、发行人/证券映射、报告期、首次发布时间、供应商接收时间、系统可用时间、修订/撤回链、原始文件链接和字段单位。
2. 对财报，保留原始申报文件与标准化XBRL/供应商字段；验证会计期间类型（瞬时值还是期间值）、币种、单位、合并口径、季度/年度累计差异。标准化数据不能取代原始申报原文。
3. 对宏观数据，保存首次值和每次修订值；记录发布日期、参考期、发布时间精度、时区和季调/非季调口径。比如首次公布的通胀值与后来修订值是两个版本，策略历史输入必须使用首次公开版本。
4. `available_at` 取该策略最早真正可消费的时点，需纳入发布源和解析延迟。日期精度不足时将信号推迟到下一交易时点；美股盘后披露不能按当日收盘价成交。
5. 对齐市场日历：周末/节假日公告、午间公告、盘后公告和跨时区公告均映射到下一个可执行时间。事件研究的 t=0 定义为公开时点之后首个可交易窗口，而非机械地用公告日期。
6. 构造 surprise 时，预期值也要 PIT：保存分析师预测、调查样本截点、最后更新时间和实际发布日期；不能用事后共识或修订共识。
7. 收益标签分开做：事件前到事件后raw价格变化、含分红总回报、基准调整收益；跨市场时明确定义当地交易日和共同可交易时段。
8. 训练/验证按事件时间分组，重叠事件要去重或显式处理标签区间；同一发行人的多个修订公告不能被误当多个独立信息事件。
9. 复盘反应窗口时同时看价格、成交、点差、波动、停牌/竞价和可执行成交成本。消息后价格跳空但交易者买不到，并不代表策略实际赚到跳空。

### 流程E：日内信号、订单流和执行质量

**目标**：研究分钟或逐笔策略、估计短期方向和执行成本，或还原订单是否可成交。

1. 先定数据覆盖与研究对象。A股选沪/深/北交所、具体产品、连续竞价/集合竞价/盘后固定价格/大宗交易；美股选 SIP 综合行情、单一 venue direct feed、场外成交报告，还是自有订单回报。不同层级不能互称“全市场盘口”。
2. 收集原始 trade、quote、订单新增/修改/撤销、序列号、成交条件、交易阶段、venue、交易所时间、接收时间和 correction/cancel 信息。保留原始消息，不先用一分钟线替代逐笔。
3. 按序列号和交易所规则重放成交更正、撤单及订单生命周期；检测序列缺口、重复包、乱序、延迟报告、锁定/交叉报价和时钟偏差。对无法确定的事件打不确定标签，而不是插值造价。
4. 按交易阶段分段：开盘/收盘竞价、连续交易、午休、盘前盘后、停牌和复牌分别建模。A股集合竞价和美股开收盘 auction 的订单不应与连续撮合的交易方向、波动和流动性统计混在一起。
5. 清理报价：使用适用的NBBO或venue内有效报价定义，剔除/标记零报价、非 firm quote、过期quote、locked/crossed 状态、超出有效时段报价。高频特征要用决策时当时可见的报价，不可用同一秒结束后的最终报价。
6. 决定抽样。执行模拟一般保留时间、事件和订单生命周期；活动特征可并列构造成交笔数/成交量/成交额柱（tick/volume/notional bars）；订单流预测才考虑不平衡/连续方向柱（imbalance/runs bars）。成交额柱按报价币种计值，跨 A 股与美股比较时需先明确点时汇率换算。成交方向无法可靠判定时保留 `unknown`，做多种分类器敏感性分析。
7. 构造bar时按证券、交易日、连续交易阶段分别处理。指定bar时间标签是开始还是结束；保留阈值超额、首末时间、trade_count、交易金额、竞价标志和不完整尾bar状态。不要把成交拆分成虚构的部分交易，也不要把超阈值交易静默丢掉。
8. 设计可成交模拟：信号产生后加通信/处理延迟，按当时订单簿和排队优先级、订单类型、价格限制及部分成交规则推进；使用限价单时不可假定触价即成交。只用OHLCV无法识别bar内先后顺序，也无法声称队列级精确模拟。
9. 扣除券商费用、交易所费、监管费、税、融资/借券、点差、冲击、路由和拒单成本；按账户真实规则设定最小交易单位、零股、A股可卖数量和美股盘前盘后权限。
10. 报告净收益、成交率、挂单等待、平均/尾部滑点、参与率、撤单率、各session表现和数据覆盖率。分别对核心时段、竞价、盘前盘后和夜间场次评估；不要用核心时段的价差模型填补低流动性场景。

**采样方法的边界**：时间 bar 每行持续时间相同但交易活动不同；成交笔数/成交量/成交额柱（tick/volume/notional bars）按不同活动量截取样本；不平衡柱（imbalance bars）按主动方向代理动态截取。它们改变观测频率和样本分布，不会保证 IID、正态、平稳或相同的信息量。阈值、方向估计、交易时段、拆股和合约乘数都可能改变结果。

### 流程F：期货、ETF与多资产篮子/相对价值

**目标**：研究跨期价差、对冲、动态ETF篮子或多资产组合，而不把不可交易的合成序列当成真实PnL。

1. 为每张合约和每只资产建有效期证券主表：到期日、乘数、最小跳动、结算方式、交易时段、币种、交割/最后交易日、ETF份额/分红、股票股数和换月规则。
2. 选择数据时点。价差模型用同步或可校正的时间戳；A股收盘早于美股核心收盘，不能把同一个自然日的两个收盘视为同时可成交。对异步报价使用共同可交易窗口或显式滞后特征。
3. 决定连续期货研究序列的规则（主力、固定提前N天、成交量/持仓切换等），生成一份逐日 roll map，记录旧/新合约、切换决策时点、当时可知的成交量/持仓和实际换仓成交。
4. 分开价格研究序列与持仓收益。若计算连续图表的加减缺口，优先用同一时刻的旧/新合约可执行报价估计期限价差；不要用新合约首个open减旧合约前收盘而把隔夜行情一起当成roll gap。调整序列用于状态/趋势特征，仓位、保证金和PnL始终按真实合约和乘数逐笔记账。
5. 股票/ETF篮子在每个调仓时点使用点时权重和上一时段持仓。权重由收盘数据得出时，只能从后续可执行价开始生效；将现金、分红、融资、借券和FX单独列账。
6. 以头寸而非单纯价格百分比计算组合变化。股票有股数 q；期货有合约数 n 和乘数 M；期权需 Delta/Gamma、合约乘数及波动率等。将各组件PnL转换到账户基准币种，再除以之前净值。
7. 在调仓时刻计算交易需求和换手，扣除双边费用、spread、市场冲击、滚动成本、借券/融资、期货展期和保证金约束。静态成本率不能替代高换手/低流动性下的容量模型。
8. ETF Trick/动态篮子适合把多组件收益转换成一个组合资金曲线，但只有在权重、同步可交易价格、cash leg、乘数、FX、公司行为和成本都对齐时才有账户意义。原手册的 `basket_wealth_index` 是滞后权重下的百分比收益示意，并非完整ETF Trick。
9. 做基差、价差平稳性和对冲比率分析时只用训练区间估计；滚动换月、到期收敛和交易日错位要纳入数据。期货负价、合约切换和远月稀疏成交会让比例收益或简单补缺失失效。
10. 做分解报表：方向收益、曲线/基差、展期、股息/carry、FX、交易费、冲击、融资保证金分别贡献多少；再与真实账户或逐合约结算价回放交叉验证。

### 流程G：A股与美股跨市场/ADR相对价值

**目标**：比较同一公司本土股与ADR、跨境指数、相关股票或时区领先滞后信号。

1. 建发行人到证券的一对多映射，保存普通股、不同投票权股、ADR比率、存托银行、挂牌地、币种和比率变更历史。ticker相似或公司名相同都不足以建立映射。
2. 取得两地 raw 价格、逐市场公司行为、交易日历、FX、交易阶段、停牌/限制、交易费、融资融券/借券和资金可转移约束。
3. 先确定估值时刻。A股午后收盘与美股盘后/夜间并不同步；用“同日收盘对同日收盘”会包含时间差和海外消息。优先选两个市场都开放的共同时间窗，或把领先市场信号滞后一侧的可交易时点。
4. 将 ADR 换算成每股/每份发行人权益的统一数量单位，再转换为同一币种；把汇率本身分解为因子或对冲掉，并对照ADR ratio、存托费用、股息预扣税和交易时差。
5. 按双方各自交易规则判断信号能否同时执行：一侧停牌、涨跌停或休市时，价差可能无法收敛交易；美股借券和A股做空工具可得性也不同。
6. 构造价差前仅用训练样本估计对冲比率、均值和阈值；单位根/协整/结构突变检验不能用全样本结果提前决定历史开仓。
7. 信号形成后以两侧下一可执行报价下单，考虑时区等待、汇率、跨境资金、券源和清算约束。回测可报告“理论价差”与“实际可实现组合PnL”两条结果。
8. 对周末、两地不同节假日、夏令时、ADR分红和公司行为日期做事件级单元核验。一次映射错误或股比方向错误就足以制造稳定的伪套利。

### 流程H：另类数据、供应链和文本信号

**目标**：使用新闻、网页、招聘、客流、信用卡、卫星、物流或供应链关系预测市场变化。

1. 合法授权和字段定义先行：记录许可范围、存储/再分发限制、删除要求、隐私属性、样本覆盖和供应商历史版本；不具备回测/生产使用权限的数据不能进入策略库。
2. 对每个观测保存“事实发生、采集、供应商处理、发布、策略收到”多个时间。历史网页快照时间、爬虫抓取时间和页面标示时间可能不同，取保守的可用时间。
3. 构建公司/产品/地点映射时保存置信度、生效区间、映射方法和人工确认记录。并购、品牌改名、供应链替换和实体歧义都要追踪，不能只按今天的公司名单回填。
4. 检查覆盖变化：供应商扩大样本、数据接口升级、历史回填和遗漏修复会造成“数据突然变好”。把覆盖率和采集方式作为特征质量变量，不要误认为经济信号。
5. 先做事件去重、机器人/重复页面过滤、单位标准化、异常值和修订处理；文本模型保存原文哈希、发布时间、模型版本、词典/提示版本和推理时间。
6. 将特征按 `available_at` 点时并入证券/事件数据。情绪模型使用未来语料或更新后的文本分类器重跑历史，也会造成模型层面的前视偏差，须冻结当时模型或做明确的历史重算标签。
7. 从特征到市场反应做因果时间检查：信号是否在价格之前可用，是否只是价格上涨后供应商覆盖同步增多，是否由同一新闻源重复带入。逐事件人工抽样核验。
8. 按供应商、地区、行业、信号来源和覆盖区间分层验证；在成本前后、不同时间段和已退市公司样本上测试稳健性。离线相关性不能证明有可执行的预测价值。

### 流程I：组合级风险、持仓和生产数据监督

**目标**：让研究信号在持仓、现金、融资、风控和实盘数据中闭环。

1. 从订单与成交回报建立实际持仓、现金、应收股息、费用、融资/借券和FX现金腿；市场行情推算持仓只做对账，不应取代账本。
2. 每个交易日用正式结算/估值价格计算净值，标明核心时段收盘、官方结算价、盘后价格和内部估值的区别；跨市场资产按各自最新可得的价格和时点标识估值新鲜度。
3. 检查头寸限制：单票/行业/国家/币种/场所敞口，参与率和ADV，A股涨跌停或停牌，券源和借券召回，期货保证金及临近交割，期权行权和到期。
4. 订单级对账：策略目标→发送订单→交易所/券商确认→部分成交→撤改单→成交回报→结算。每条状态都保留序号和时间；未确认订单不能假设成交，已撤订单不能计入持仓。
5. 生产风险控制读取当时行情状态和制度规则，建立失联、行情过期、价格超限、规则切换、分红拆股、停牌复牌和异常波动的熔断告警。
6. 每日将预期与实际拆解：信号收益、选择收益、持仓收益、公司行为、FX、融资、交易费、spread/impact、未成交机会成本和数据延迟。残差无法解释时先排查行情定义、持仓和公司行为。
7. 对数据源延迟、缺包、字段变化、修订、异常覆盖率设阈值；出现问题时冻结对应策略数据版本并触发回放，不静默用前值补齐。

## 4. 点时合并和收益计算的最小代码模板

下面代码只展示点时准入和收益口径的边界。生产实现必须根据具体数据表加证券主键、公司行为类型、版本优先级、交易日历和缺失策略。

### 4.1 点时合并：只连接当时可用的版本

```python
import pandas as pd

def point_in_time_join(decisions, releases, tolerance=None, allow_exact_matches=False):
    """每个 security_id + feature_id 使用决策时点之前最新可用的版本。

    decision_time 和 available_at 必须是带时区时间；函数会先统一转换为 UTC。
    releases 中相同证券、特征、available_at 若有多个版本，调用者必须先按
    source priority / revision sequence 留下唯一且可解释的版本。
    tolerance 应按字段的经济有效期显式设定；None 表示不额外施加统一过期阈值。
    只有可靠时序能证明披露先于决策时，才将 allow_exact_matches 设为 True。
    """
    if not isinstance(allow_exact_matches, bool):
        raise TypeError("allow_exact_matches must be a bool")
    def to_utc_series(values):
        converted = []
        for value in values:
            ts = pd.Timestamp(value)
            if ts.tzinfo is None:
                raise ValueError("timestamps must include a timezone; normalize source-local time first")
            converted.append(ts.tz_convert("UTC"))
        return pd.Series(converted, index=values.index)

    keys = ["security_id", "feature_id"]
    left = decisions.copy()
    right = releases.copy()
    left["decision_time"] = to_utc_series(left["decision_time"])
    right["available_at"] = to_utc_series(right["available_at"])
    if right.duplicated(keys + ["available_at"]).any():
        raise ValueError("resolve duplicate UTC point-in-time releases before joining")

    left = left.sort_values("decision_time")
    right = right.sort_values("available_at")
    kwargs = {}
    if tolerance is not None:
        kwargs["tolerance"] = pd.Timedelta(tolerance)

    out = pd.merge_asof(
        left,
        right,
        left_on="decision_time",
        right_on="available_at",
        by=keys,
        direction="backward",
        allow_exact_matches=allow_exact_matches,
        **kwargs,
    )
    return out
```

`allow_exact_matches=False` 是保守默认；若事件时间有更高精度且序列顺序证明披露先于策略决策，可显式允许相等。对财报类字段还要将每份披露事实绑定到报告期间/单位/会计口径；只按公司和日期匹配可能把旧期间数值错当最新经营值。

### 4.2 用持仓现金流而不是复权价代替账户收益

股票组合每期净值可写成：

```text
NAV_t = cash_t + Σ_i shares_i,t × raw_price_i,t × FX_i,t
        + dividend_receivable_t + other_assets_t - liabilities_t
portfolio_return_t = NAV_t / NAV_(t-1) - 1
```

拆股改变 `shares` 与每股 `raw_price` 的数量单位；现金分红进入现金或应收；买卖成交改变股数与现金；费用、税、融资和FX变动进入对应账本。后复权/总回报指数适合做交叉核验或展示，不应掩盖真实持仓路径。

### 4.3 bar 构造的必须参数

无论使用成交笔数/成交量/成交额柱（tick/volume/notional bars）还是不平衡柱（imbalance bars），代码入口至少要显式要求：证券、交易日、session、时间戳定义、成交条件过滤口径、交易方向来源、阈值单位、超阈值交易处理方式、不完整尾bar规则和数据版本。成交额柱的金额阈值必须注明报价币种；A 股与美股样本需要统一币种时，应使用点时汇率和明确的换算时刻。超过阈值的一笔成交整体归入会使 bar 活动量超限；这是合理的一种定义，但不同于把成交拆分或把余额结转，研究中必须固定同一种定义。书中有关 CUSUM、活动 bar、标签重叠和微观结构的做法可以作为研究方法起点，不代表现成的数据定义适用于所有供应商。

## 5. 策略数据进入回测前的放行条件

仅当以下问题都能回答时，才将数据集标记为可用于正式回测：

- 决策时点之前有哪些记录可用？数据供应和解析延迟是否重建？
- 股票池、指数成分、行业、股本、借券和状态是否按历史时点还原？
- 价格究竟是raw、split-adjusted、前复权、后复权还是total return？供应商的现金分红/再投资/体现在volume里的方式是否核对？
- 每个成交价属于哪个session/venue？是否包含竞价、场外、延迟报告、撤销和更正？
- 规则表按什么日期生效？交易单位、涨跌停、可卖时点、停牌、LULD和竞价是否纳入？
- 特征和标签的时间区间是否有泄露？预处理参数是否只从训练期估计？
- 成交模型是否按真实决策延迟、订单类型、可成交量、容量和成本执行？
- 收益能否由底层持仓、现金、公司行为、费用和汇率重放？
- 数据修订后能否复现上一个历史版本并说明回测变化？

任一关键项缺失，都应给数据集标注用途边界：低频探索、信号研究、执行级回测或生产交易。不能把低质量研究行情包装成执行级证据。
